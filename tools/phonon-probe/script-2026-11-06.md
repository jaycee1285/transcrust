# Four-paragraph microphone read: six versus twelve seconds

Input: local corpus `2026-11-06T22-28-33Z.wav` + JSON, 122.24s at 44.1kHz.
John stopped after four paragraphs because the script was too difficult to
read naturally. The intended excerpt has 200 words, not the full 500. This is
a phonetic stress read, not an ordinary-dictation accuracy benchmark.

## Same-audio result

| Observation | Six-second cap | Twelve-second cap |
|---|---:|---:|
| Independent windows | 28 | 12 |
| Disagreements with 200-word written excerpt | 22 | 14 |
| After removing recognized paragraph-marker phrases | 16 | 10 |
| Windows whose Rust text matches C exactly | 28/28 | 12/12 |

Counts normalize case and remove punctuation. They are **script disagreement,
not verified WER**: the recording includes paragraph commands and possible
reading slips, and spoken ground truth has not been independently checked.
Removing “new paragraph” / “in paragraph” is a content-only diagnostic, not a
claim that both commands were recognized correctly. It excludes a command that
six seconds retained before paragraph two and twelve seconds omitted.

Twelve-second replay also reproduces the raw live transcript exactly. No DEC
candidates occurred in the live take, so the model made zero correction edits.
Deterministic cleanup handled one recognized paragraph marker and capitalization.

There are improvements and regressions; twelve is closer to the written
passage overall. The “cluttered her” case is especially useful: six starts a
new window at 109.845s with “Clennard Hert rehearsal,” whereas twelve keeps
that phrase inside its 105.075–114.285s window and returns “cluttered her.”
This is a directly observed sensitivity to changing window boundaries on the
same samples; it does not isolate which internal normalization/context effect
caused the different choice.

## Live latency and state

The twelve-second live path processed eleven completed windows while recording.
Post-stop ASR wait was **1.605s** and decision overhead 7ms. The recorded time
to starting injection was **1.62s**; typing the whole output then took several
more seconds. This verifies that dispatch during capture worked on the human
take. It is not a measured six-versus-twelve latency benchmark. Interleaved
offline Rust/C timings are not substituted for live timing.

Leave twelve selected for ordinary dogfood; no model/glossary/prompt changes.
Human quality acceptance remains open. No need to finish the tongue-twister
script or rerecord this comparison.
